This is not a manifesto. It is a system test for the new site: a real content
entry that exercises the surfaces needed for durable technical writing.

The first design constraint is simple: the writing must be able to hold an
argument without leaning on the surrounding interface. The page has to support
technical depth, professional memory, and enough editorial structure to be
cited later.

## An Image Comparison

Two images that differ in one respect are easier to read as a wipe than as a
pair. `ImageCompare` puts them in a single frame behind a divider the reader
drags:

<ImageCompare
  first={controlLoopOpen}
  second={controlLoop}
  firstAlt="The same block diagram with no return path from the plant back to the sensor."
  secondAlt="A block diagram showing sensor input, estimation, control, actuation, and plant feedback."
  firstLabel="Open loop"
  secondLabel="Closed loop"
  caption="Drag the divider: the only difference between the two diagrams is the return path."
  width="wide"
/>

Both images must share dimensions. The frame takes its size from `second`, so a
`first` with a different aspect ratio gets cropped to fit. This suits A/B design
options and before-and-after states; it is the wrong surface for two images that
merely sit near each other, which is what `Gallery` is for.

## Code

Code blocks should feel native to the document and keep copy-and-paste fidelity.

```rust
fn saturating_deadband(input: i16, threshold: i16) -> i16 {
    if input.abs() < threshold {
        0
    } else {
        input
    }
}
```

Inline code such as `u16::MAX` should sit naturally inside a sentence.

## Mathematical Notation

Inline math works: $e^{i\pi} + 1 = 0$.

Display math works too:

$$
x_{k+1} = A x_k + B u_k
$$

Equations should be build-time rendered and readable in both light and dark
themes.
